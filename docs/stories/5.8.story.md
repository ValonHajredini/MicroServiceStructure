# Story 5.8: Performance Optimization & Launch Prep

## Status
Draft

## Story

**As a** platform operator,
**I want** performance optimized and launch checklist completed,
**so that** we meet our SLA commitments.

## Acceptance Criteria

1. Database indexes created on frequently queried fields (tenant_id, user_id, created_at)
2. API response times tested: <200ms p95 for CRUD operations verified
3. Load testing performed: 50 concurrent users, all services remain responsive
4. Connection pooling configured for database connections (max pool size: 20 per service)
5. Static assets (Angular builds) served with caching headers and compression
6. Launch checklist completed: security audit, backups verified, monitoring active, documentation published
7. Go/no-go decision made based on: all tests passing, uptime >99% in staging for 48 hours

## Tasks / Subtasks

- [ ] Task 1: Optimize Database Layer (AC: 1, 4)
  - [ ] Review and apply indexes for `tenant_id`, `user_id`, and `created_at` on Core, Notes, Kanban databases (if not already present)
  - [ ] Configure TypeORM connection pooling with max pool size of 20 and document environment variables controlling pool limits
  - [ ] Validate query plans post-indexing to ensure improved performance

- [ ] Task 2: Backend Performance Validation (AC: 2, 3)
  - [ ] Create load testing scripts (k6, Artillery, or JMeter) covering CRUD workflows for each service
  - [ ] Execute tests simulating 50 concurrent users and capture latency metrics
  - [ ] Document performance results, highlighting p95 response times meeting <200ms target

- [ ] Task 3: Frontend Asset Optimization (AC: 5)
  - [ ] Configure Angular builds with compression (gzip/brotli) and long-lived caching headers in Nginx/App Platform
  - [ ] Verify static assets served with appropriate cache-control and content-encoding headers
  - [ ] Measure Lighthouse scores to confirm page load goals

- [ ] Task 4: Launch Checklist Finalization (AC: 6)
  - [ ] Consolidate outputs from security audit (Story 5.4), monitoring (Story 5.5), deployment (Story 5.6), and E2E testing (Story 5.7)
  - [ ] Update `docs/launch/launch-checklist.md` with verification status for each readiness item
  - [ ] Ensure documentation (API, deployment, runbooks) published and accessible

- [ ] Task 5: Go/No-Go Readiness Review (AC: 6, 7)
  - [ ] Monitor staging environment uptime (>99%) over 48 hours using observability stack
  - [ ] Host go/no-go meeting capturing decision, risks, and contingencies
  - [ ] Record final decision and approvals in launch checklist documentation

- [ ] Task 6: Regression & Sign-off (AC: 2, 3, 7)
  - [ ] Re-run E2E suites and critical unit/integration tests after optimizations
  - [ ] Ensure monitoring alerts remain quiet during performance tests (no false positives)
  - [ ] Archive performance reports, configs, and meeting notes for audit trail
