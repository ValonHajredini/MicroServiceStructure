### Multi-Tenancy Pattern Overview

[Source: architecture/database-architecture.md#multi-tenancy-pattern]

**Shared-Schema Multi-Tenancy:**
Every table in every service database includes a `tenant_id` column. All queries MUST automatically filter by the current tenant's ID to prevent cross-tenant data access.

**Critical Security Requirement:**
A developer should NEVER need to manually add `WHERE tenant_id = ?` to queries. The system must enforce this automatically to prevent security vulnerabilities from human error.

### Database Schema Pattern

[Source: architecture/database-architecture.md]

**Every entity follows this pattern:**

```sql
CREATE TABLE notes (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL,  -- REQUIRED on all tables
    user_id UUID NOT NULL,
    title VARCHAR(500),
    content TEXT,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_notes_tenant_id ON notes(tenant_id);  -- Performance
```

**TypeORM Entity Pattern:**

```typescript
@Entity('notes')
export class Note {
  @PrimaryGeneratedColumn('uuid')
  id: string;

  @Column('uuid')
  tenant_id: string;  // Must be on EVERY entity

  @Column('uuid')
  user_id: string;

  @Column()
  title: string;

  @Column('text', { nullable: true })
  content: string;

  @CreateDateColumn()
  created_at: Date;

  @UpdateDateColumn()
  updated_at: Date;
}
```

### Tenant Context Implementation

[Source: architecture/authentication-multi-tenancy.md#multi-tenancy-implementation]

**The POC must implement this pattern:**

1. **AsyncLocalStorage for Tenant Context:**
   - NestJS middleware extracts tenantId from JWT (req.user.tenantId)
   - Store tenantId in AsyncLocalStorage for request scope
   - All repository operations retrieve tenantId from AsyncLocalStorage

2. **Middleware Pattern:**
```typescript
@Injectable()
export class TenantContextMiddleware implements NestMiddleware {
  constructor(private tenantContext: TenantContextService) {}

  use(req: any, res: any, next: () => void) {
    const user = req.user;  // Set by JwtStrategy from Story 1.2
    if (!user || !user.tenantId) {
      throw new UnauthorizedException('Tenant context missing');
    }

    // Set tenant context for this request
    this.tenantContext.run(user.tenantId, () => {
      next();
    });
  }
}
```

3. **Base Repository with Auto-Filtering:**
```typescript
export class TenantScopedRepository<T> extends Repository<T> {
  constructor(
    private tenantContext: TenantContextService,
    private entityTarget: EntityTarget<T>,
    manager: EntityManager
  ) {
    super(entityTarget, manager);
  }

  async find(options?: FindManyOptions<T>): Promise<T[]> {
    const tenantId = this.tenantContext.getTenant();
    return super.find({
      ...options,
      where: {
        ...options?.where,
        tenant_id: tenantId  // Automatically inject
      }
    });
  }

  // Override findOne, save, update, remove similarly
}
```

### Security Testing Requirements

[Source: architecture/security-architecture.md#threat-model]

**The POC MUST test these threat scenarios:**

1. **Cross-Tenant Read Attack:**
   - Tenant A creates note with id=123
   - Tenant B attempts: `repository.findOne({ where: { id: 123 } })`
   - **Expected:** Query returns null (note not found)
   - **Verify SQL:** `SELECT * FROM notes WHERE id = 123 AND tenant_id = 'tenant-b'`

2. **Cross-Tenant Update Attack:**
   - Tenant B attempts: `repository.update(123, { title: 'Hacked' })`
   - **Expected:** Zero rows updated
   - **Verify SQL:** `UPDATE notes SET title = 'Hacked' WHERE id = 123 AND tenant_id = 'tenant-b'`

3. **Cross-Tenant Delete Attack:**
   - Tenant B attempts: `repository.delete(123)`
   - **Expected:** Zero rows deleted
   - **Verify SQL:** `DELETE FROM notes WHERE id = 123 AND tenant_id = 'tenant-b'`

4. **Bulk Operation Isolation:**
   - Tenant A has 10 notes, Tenant B has 5 notes
   - Tenant B calls: `repository.find()`
   - **Expected:** Returns only 5 notes (Tenant B's)

5. **Missing Tenant Context:**
   - Clear AsyncLocalStorage (simulate missing context)
   - Attempt any query
   - **Expected:** Throw error, NOT return all tenants' data

### AsyncLocalStorage Pattern

AsyncLocalStorage provides request-scoped context without passing tenantId through every function:

```typescript
import { AsyncLocalStorage } from 'async_hooks';

@Injectable()
export class TenantContextService {
  private readonly asyncLocalStorage = new AsyncLocalStorage<string>();

  run(tenantId: string, callback: () => void) {
    this.asyncLocalStorage.run(tenantId, callback);
  }

  getTenant(): string {
    const tenantId = this.asyncLocalStorage.getStore();
    if (!tenantId) {
      throw new Error('Tenant context not set');
    }
    return tenantId;
  }
}
```

### Known Limitations to Document

1. **Raw SQL Queries:** TypeORM raw queries bypass entity repositories and may not include tenant filter
2. **QueryBuilder Complexity:** Complex joins may require explicit tenant filtering
3. **Performance Impact:** Extra WHERE clause on every query (mitigated by indexing)
4. **Developer Discipline:** Developers must use BaseRepository, not raw Repository
