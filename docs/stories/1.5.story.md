### Database Schema

**Password Reset Tokens Table:**
```sql
CREATE TABLE password_reset_tokens (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    token_hash VARCHAR(255) NOT NULL UNIQUE,
    expires_at TIMESTAMP NOT NULL,
    created_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_password_reset_tokens_token ON password_reset_tokens(token_hash);
CREATE INDEX idx_password_reset_tokens_user_id ON password_reset_tokens(user_id);
CREATE INDEX idx_password_reset_tokens_expires ON password_reset_tokens(expires_at);
```

**Why hash tokens?**
If database is compromised, hashed tokens prevent immediate account takeover. Attacker needs both the database AND the unhashed token from the email.

### TypeORM Entity

```typescript
@Entity('password_reset_tokens')
export class PasswordResetToken {
  @PrimaryGeneratedColumn('uuid')
  id: string;

  @Column({ type: 'uuid' })
  user_id: string;

  @Column({ type: 'varchar', length: 255, unique: true })
  token_hash: string;

  @Column({ type: 'timestamp' })
  expires_at: Date;

  @CreateDateColumn()
  created_at: Date;

  @ManyToOne(() => User)
  @JoinColumn({ name: 'user_id' })
  user: User;
}
```

### Forgot Password Flow

**Step-by-step process:**

1. **Receive Email:**
   - Extract email from request body
   - Validate email format

2. **Find User (Silently):**
   - Query: `SELECT * FROM users WHERE email = ?`
   - If not found: Still return success (prevent email enumeration)
   - If found: Continue to next step

3. **Generate Secure Token:**
   - Use: `crypto.randomBytes(32).toString('hex')` (64-char hex string)
   - This is the unhashed token sent in email

4. **Hash Token:**
   - Use: `crypto.createHash('sha256').update(token).digest('hex')`
   - OR use bcrypt (slower but more secure)
   - Store only the hash in database

5. **Store Token:**
   - Delete any existing tokens for this user (invalidate old requests)
   - Insert new token with expires_at = now + 1 hour
   - Link to user_id

6. **Send Email:**
   - Construct reset link: `https://yourdomain.com/reset-password?token={token}`
   - Send email asynchronously
   - Email template should include clear instructions

7. **Return Success:**
   - HTTP 200 OK
   - Generic message: "If the email exists, a reset link has been sent"
   - NEVER reveal if email was found or not

### Reset Password Flow

**Step-by-step process:**

1. **Receive Token and New Password:**
   - Extract token and newPassword from request
   - Validate newPassword meets strength requirements

2. **Hash Incoming Token:**
   - Hash the token from request: `crypto.createHash('sha256').update(token).digest('hex')`
   - Use same hashing method as storage

3. **Find Token Record:**
   - Query: `SELECT * FROM password_reset_tokens WHERE token_hash = ?`
   - Include user relation

4. **Validate Token:**
   - If not found: Return 400 "Invalid or expired token"
   - If expires_at < now: Return 400 "Token has expired"
   - If valid: Continue

5. **Update Password:**
   - Hash new password with bcrypt (10 rounds)
   - Update: `UPDATE users SET password_hash = ? WHERE id = ?`

6. **Invalidate Token:**
   - Delete: `DELETE FROM password_reset_tokens WHERE id = ?`
   - This ensures token can only be used once

7. **Return Success:**
   - HTTP 200 OK
   - Message: "Password reset successful. Please login with your new password."

### Email Service Integration

[Source: architecture/executive-architecture-summary.md]

**Email Provider Options:**
- **SendGrid**: Simple API, 100 emails/day free tier
- **AWS SES**: Pay per email, reliable, requires verification

**EmailService Pattern:**

```typescript
@Injectable()
export class EmailService {
  private transporter; // SendGrid or AWS SES client

  constructor() {
    // Initialize email client with API keys from env
  }

  async sendPasswordResetEmail(email: string, resetToken: string): Promise<void> {
    const resetLink = `${process.env.FRONTEND_URL}/reset-password?token=${resetToken}`;

    const emailContent = {
      to: email,
      from: process.env.EMAIL_FROM,
      subject: 'Password Reset Request',
      html: `
        <p>You requested a password reset.</p>
        <p>Click the link below to reset your password:</p>
        <a href="${resetLink}">${resetLink}</a>
        <p>This link expires in 1 hour.</p>
        <p>If you didn't request this, please ignore this email.</p>
      `
    };

    await this.transporter.send(emailContent);
  }
}
```

### Security Considerations

[Source: architecture/security-architecture.md]

**1. Token Security:**

- Hash tokens before storage (SHA256 or bcrypt)
- 1-hour expiration (short window)

- Always return success, even if email not found
- Same response time regardless of email existence
- Generic success message

export class ResetPasswordDto {
  @IsString()

  @IsString()

### Important Notes

1. **Email Service Required:** This story requires integrating an email service. Choose SendGrid for simplicity or AWS SES for production.

2. **Token Security:** Tokens MUST be cryptographically secure. Never use simple random strings or sequential IDs.

3. **Single-Use Tokens:** Tokens must be deleted after use to prevent replay attacks.

4. **Generic Messages:** Never reveal whether an email exists in the system. This prevents user enumeration.

5. **Expiration:** 1-hour expiration balances security and user convenience. Shorter is more secure but may frustrate users.

6. **Async Email:** Send emails asynchronously to avoid blocking the HTTP response. Consider using a queue in future stories.
