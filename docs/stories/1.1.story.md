## Dev Notes

### Architecture Context

This is the foundational story that establishes the entire project structure. The monorepo pattern is critical for code sharing and consistent tooling across all microservices.

**Key Architecture Decisions Referenced:**
- ADR-008: Monorepo with Nx/Turborepo - Decision to use monorepo for shared types and dependency management [Source: architecture/architecture-decision-records.md#adr-008]

### Project Structure Specification

The final structure must align with this pattern [Source: architecture/system-architecture-overview.md, architecture/component-architecture.md, architecture/infrastructure-deployment.md]:

```
MicroServiceStructure/
├── apps/
│   ├── core-api/          # NestJS - Auth, tenants, users, files
│   ├── core-ui/           # Angular 20 - Landing, auth, dashboard
│   ├── notes-api/         # NestJS - Notes service (future)
│   ├── kanban-api/        # NestJS - Kanban service (future)
│   └── admin-api/         # NestJS - Admin service (future)
├── libs/
│   └── shared-types/      # Shared TypeScript interfaces/DTOs
│       └── src/
│           ├── auth/      # JWT, user, auth types
│           ├── tenants/   # Tenant types
│           └── notes/     # Note types (future)
├── docker/                # Docker compose and configurations
├── docs/                  # Project documentation (PRD, Architecture, Stories)
├── .turbo/                # Turbo cache (gitignored)
├── package.json           # Root workspace configuration
├── turbo.json             # Turborepo pipeline configuration
└── README.md              # Monorepo documentation
```

### Technology Stack Details

[Source: architecture/executive-architecture-summary.md]

**Backend (NestJS):**
- Framework: NestJS (TypeScript-based)
- ORM: TypeORM
- Database: PostgreSQL
- Authentication: JWT with HS256

**Frontend (Angular):**
- Framework: Angular 20
- UI Library: PrimeNG
- TypeScript: Latest

**Monorepo Tool:**
- Turborepo (chosen for simpler configuration than Nx)

### Shared Types Library Structure

The libs/shared-types workspace MUST include this initial structure [Source: architecture/api-contracts-communication.md#shared-types-library]:

**JwtPayload Interface:**
```typescript
export interface JwtPayload {
  sub: string;          // User ID
  email: string;
  tenantId: string;
  roles: string[];      // ['admin', 'user']
  enabledServices: string[];  // ['notes', 'kanban']
  iat: number;
  exp: number;
}
```

This interface is critical as it defines the authentication contract across ALL services.

### Workspace Configuration Requirements

**Root package.json must include:**
- Workspaces definition pointing to apps/*, libs/*
- Turborepo dev dependency
- Common dev dependencies: TypeScript, ESLint, Prettier

**Each workspace package.json must:**
- Use proper naming convention: @microservice/workspace-name
- Define its own dependencies
- Include scripts that work with Turbo pipeline

### Turbo.json Pipeline Configuration

[Source: architecture/infrastructure-deployment.md#cicd-pipeline]

The turbo.json MUST define these pipelines:
- **build**: Builds all services and libraries (libs should build before apps)
- **dev**: Runs development servers for services
- **test**: Runs all unit/integration tests
- **lint**: Runs ESLint across all workspaces

Pipeline dependencies must ensure libs build before apps that depend on them.

### Initial Services to Configure

**This story only sets up TWO initial workspaces:**
1. **apps/core-api** - NestJS backend for authentication service
2. **apps/core-ui** - Angular 20 frontend for core UI

Other services (notes-api, kanban-api, admin-api) will be added in future stories.

### Testing

#### Test Requirements
No specific testing required for this foundational story. Focus is on:
1. Verifying all Turbo commands execute without errors
2. Confirming workspace resolution works correctly
3. Ensuring shared-types can be imported by both core-api and core-ui

#### Verification Steps
- Run `turbo build` - should build libs/shared-types first, then apps
- Run `turbo dev` - should start both core-api and core-ui dev servers
- Run `turbo lint` - should lint all workspaces
- Verify shared-types imports work in both core-api and core-ui

### Important Notes

1. **No Code Implementation Yet**: This story ONLY sets up structure. No business logic, authentication, or database code should be written.

2. **Minimal Shared Types**: Only create the base interfaces needed. Full type definitions will be added as services are built.

3. **Docker Directory**: Create the docker/ directory but leave it empty. Docker configurations will be added in Story 1.7.

4. **Documentation First**: The README.md is critical - future developers and AI agents will rely on it to understand the monorepo structure.
