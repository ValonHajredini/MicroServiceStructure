# Story 2.5: Service Enablement Configuration

## Status
Draft

## Story

**As a** tenant admin,
**I want** to enable/disable services for my organization,
**so that** I only pay for and see services I need.

## Acceptance Criteria

1. PATCH /tenants/:id/services endpoint accepts array of service names: ["notes", "kanban", "forms"]
2. Tenant enabled_services field updated in database
3. Future JWT tokens include updated enabledServices claim
4. GET /tenants/:id endpoint returns current enabled services
5. Only tenant admins can modify service enablement
6. Invalid service names rejected with validation error
7. Dashboard UI immediately reflects service availability changes

### JWT Payload Update

[Source: AC 3, architecture/api-contracts-communication.md#shared-types-library]

**JWT Payload Interface**:
```typescript
// libs/shared-types/src/auth/jwt-payload.interface.ts
export interface JwtPayload {
  sub: string;          // User ID
  email: string;
  tenantId: string;
  roles: string[];      // ['admin', 'user']
  enabledServices: string[];  // ['notes', 'kanban'] - CRITICAL FIELD
  iat: number;
  exp: number;
}
```

**JWT Generation**:
```typescript
// core-api/src/auth/auth.service.ts
async generateToken(user: User): Promise<string> {
  const tenant = await this.tenantsRepo.findOne({ 
    where: { id: user.tenantId } 
  });
  
  const payload: JwtPayload = {
    sub: user.id,
    email: user.email,
    tenantId: user.tenantId,
    roles: user.roles,
    enabledServices: tenant.enabled_services || [], // Include services
    iat: Date.now() / 1000,
    exp: Date.now() / 1000 + 86400  // 24 hours
  };
  
  return this.jwtService.sign(payload);
}
```

**Important**: When tenant enabled_services change, existing JWT tokens still have old services. User must get new token (re-login or refresh) to see changes.

// auth.service.ts
async refreshToken(): Promise<string> {
  const response = await this.http.post<AuthResponse>(
    `${environment.apiUrl}/api/v1/auth/refresh`,
    {}
  ).toPromise();
  
  localStorage.setItem('auth_token', response.data.token);
  return response.data.token;
}

// service-management.component.ts

### Service Access Authorization (Future)

[Source: AC 7, future integration needs]

Create guard for service-specific endpoints:

// guards/service-enabled.guard.ts
@Injectable()
export class ServiceEnabledGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const request = context.switchToHttp().getRequest();
    const user = request.user; // From JWT
    const requiredService = this.reflector.get<string>(
      'service',
      context.getHandler()
    );
    
    if (!requiredService) return true;
    
    return user.enabledServices?.includes(requiredService);
  }
}

  // Only accessible if 'notes' in enabledServices

### Validation Logic

[Source: AC 6]

**Backend Validation**:
```typescript
// tenants.service.ts
async updateServices(tenantId: string, services: string[]): Promise<Tenant> {
  // Validate service names
  const invalidServices = services.filter(
    s => !VALID_SERVICES.includes(s)
  );
  
  if (invalidServices.length > 0) {
    throw new BadRequestException({
      message: `Invalid service name(s): ${invalidServices.join(', ')}`,
      validServices: VALID_SERVICES
    });
  }
  
  // Update tenant
  await this.tenantsRepo.update(tenantId, {
    enabled_services: services
  });
  
  return this.tenantsRepo.findOne({ where: { id: tenantId } });
}
```

### Authorization Guards

[Source: AC 5]

**Admin-Only Access**:
```typescript
@Patch(':id/services')
@UseGuards(JwtAuthGuard, RolesGuard)
@Roles('admin')
async updateServices(
  @Param('id') id: string,
  @Body() dto: UpdateServicesDto,
  @CurrentUser() user: any
) {
  // Verify user is admin of this tenant
  if (user.tenantId !== id) {
    throw new ForbiddenException('You can only modify your own tenant');
  }
  
  return this.tenantsService.updateServices(id, dto.services);
}
```

### Business Logic Rules

[Source: AC 1-7, derived requirements]

1. **Array Replacement**: PATCH replaces entire services array (not additive)
2. **Empty Array Allowed**: Tenant can disable all services (enabled_services = [])
3. **Admin Authority**: Only tenant admins can modify services
4. **Self-Service Only**: Admins can only modify their own tenant's services
5. **Validation**: All service names must be in VALID_SERVICES enum
6. **JWT Update**: Changes only reflected after new JWT issued (re-login or refresh)
7. **Immediate DB Update**: Database updated immediately, JWT updated on next auth

### Error Handling

**Backend Errors**:

- Not admin: "Only tenant administrators can modify services"

### Security Considerations

[Source: architecture/security-architecture.md]

1. **Authorization**: Admin-only endpoint, tenant ownership verified
2. **Validation**: Strict enum validation prevents invalid service names
3. **SQL Injection**: JSONB field handled safely by TypeORM
4. **Token Security**: Service list in JWT is read-only, can't be modified by client
5. **Audit Trail**: Consider logging service changes (future enhancement)
