# Story 3.2: Notes API - CRUD Operations

## Status
Draft

## Story

**As a** user,
**I want** to create, read, update, and delete notes,
**so that** I can capture and manage my information.

## Acceptance Criteria

1. POST /notes endpoint creates note with title, content, folder_id (optional)
2. Note automatically scoped to tenant from JWT, user_id from token
3. GET /notes endpoint returns paginated note list filtered by tenant_id
4. GET /notes/:id endpoint returns single note with attachments
5. PATCH /notes/:id endpoint updates title, content, folder_id, is_pinned
6. DELETE /notes/:id soft deletes note (sets deleted_at timestamp)
7. Only note owner or tenant admin can update/delete notes

### NestJS Service Pattern

**Repository Injection Pattern**:  
[Source: architecture/component-architecture.md#notes-service]

```typescript
// notes.service.ts
@Injectable()
export class NotesService {
  constructor(
    @InjectRepository(Note) private notesRepo: Repository<Note>
  ) {}

  async create(createNoteDto: CreateNoteDto, tenantId: string, userId: string): Promise<Note> {
    const note = this.notesRepo.create({
      ...createNoteDto,
      tenant_id: tenantId,  // Auto-inject from JWT
      user_id: userId        // Auto-inject from JWT
    });
    return this.notesRepo.save(note);
  }

  async findAll(tenantId: string, options: PaginationOptions): Promise<PaginatedResult<Note>> {
    const { page = 1, limit = 20, folder_id } = options;
    
    const queryBuilder = this.notesRepo.createQueryBuilder('note')
      .where('note.tenant_id = :tenantId', { tenantId })
      .andWhere('note.deleted_at IS NULL');
    
    if (folder_id) {
      queryBuilder.andWhere('note.folder_id = :folder_id', { folder_id });
    }
    
    const [notes, total] = await queryBuilder
      .orderBy('note.is_pinned', 'DESC')
      .addOrderBy('note.updated_at', 'DESC')
      .skip((page - 1) * limit)
      .take(limit)
      .getManyAndCount();
    
    return {
      data: notes,
      meta: {
        page,
        limit,
        total,
        totalPages: Math.ceil(total / limit)
      }
    };
  }

  async softDelete(id: string, tenantId: string, userId: string): Promise<void> {
    const note = await this.findOne(id, tenantId);
    
    // Authorization check
    if (note.user_id !== userId && !user.roles.includes('admin')) {
      throw new ForbiddenException('You can only delete your own notes');
    }
    
    // Soft delete note
    await this.notesRepo.update(id, { deleted_at: new Date() });
    
    // Soft delete attachments
    await this.attachmentsRepo.update(
      { note_id: id },
      { deleted_at: new Date() }
    );
  }
}
```

### Authorization Logic

**Resource Ownership Check**:  
[Source: AC 7 and Epic requirements]

```typescript
// Can user modify this note?
function canModifyNote(note: Note, user: JwtPayload): boolean {
  return note.user_id === user.userId || user.roles.includes('admin');
}

// Usage in controller
@Patch(':id')
async update(@Param('id') id: string, @Body() dto: UpdateNoteDto, @CurrentUser() user: JwtPayload) {
  const note = await this.notesService.findOne(id, user.tenantId);
  
  if (!canModifyNote(note, user)) {
    throw new ForbiddenException('You can only modify your own notes');
  }
  
  return this.notesService.update(id, dto);
}
```

### Inter-Service Communication

**Calling Core Service for File Metadata**:  
[Source: architecture/api-contracts-communication.md#inter-service-communication]

```typescript
// files-client.service.ts
@Injectable()
export class FilesClientService {
  constructor(private httpService: HttpService) {}

  async getFileMetadata(fileId: string, token: string): Promise<FileMetadata> {
    const coreServiceUrl = process.env.CORE_SERVICE_URL || 'http://localhost:3000';
    
    try {
      const response = await this.httpService
        .get(`${coreServiceUrl}/api/v1/files/${fileId}`, {
          headers: { Authorization: `Bearer ${token}` }
        })
        .toPromise();

      return response.data.data;
    } catch (error) {
      if (error.response?.status === 404) {
        throw new NotFoundException(`File ${fileId} not found`);
      }
      throw new ServiceUnavailableException('Core Service unavailable');
    }
  }
}
```

## Testing

### Testing Standards

**Framework**: Jest  
**Test File Pattern**: `*.spec.ts` files co-located with source files

**Coverage Requirements**:
- All controller endpoints must have unit tests
- All service methods must have unit tests
- Integration tests for full CRUD flows
- Authorization tests for ownership checks

**Key Test Scenarios**:

1. **Create Note Tests**:
   - Creates note with valid data
   - Auto-assigns tenant_id and user_id from JWT
   - Validates folder belongs to tenant
   - Returns 400 for invalid data
   - Returns 404 if folder doesn't exist

2. **List Notes Tests**:
   - Returns paginated notes filtered by tenant
   - Excludes deleted notes (deleted_at IS NULL)
   - Orders by: pinned first, then updated_at DESC
   - Filters by folder_id if provided
   - Respects pagination (page, limit)

3. **Get Note Tests**:
   - Returns note with attachments
   - Returns 404 for note in different tenant
   - Returns 404 for deleted note
   - Includes file metadata from Core Service

4. **Update Note Tests**:
   - Updates allowed fields (title, content, folder_id, is_pinned)
   - Enforces ownership (user owns note OR user is admin)
   - Returns 403 if user not authorized
   - Returns 404 if note doesn't exist
   - Validates folder belongs to tenant

5. **Delete Note Tests**:
   - Soft deletes note (sets deleted_at)
   - Soft deletes all attachments
   - Enforces ownership (user owns note OR user is admin)
   - Returns 403 if user not authorized
   - Returns 404 if note doesn't exist

6. **Tenant Isolation Tests**:
   - Tenant A cannot see tenant B's notes
   - Tenant A cannot update tenant B's notes
   - Tenant A cannot delete tenant B's notes

7. **Authorization Tests**:
   - Note owner can update their note
   - Admin can update any note in their tenant
   - Non-admin cannot update other users' notes
   - Same rules apply for delete
