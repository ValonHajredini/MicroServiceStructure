## Story

**As a** user,
**I want** to create and manage tasks within columns,
**so that** I can track work items.

## Acceptance Criteria

1. POST /columns/:columnId/tasks endpoint creates task with title, description, assigned_to, priority, due_date
2. Task automatically assigned tenant_id, board_id (from column), position (bottom of column)
3. GET /tasks/:id endpoint returns task with comments
4. PATCH /tasks/:id endpoint updates title, description, assigned_to, priority, due_date, column_id (for moves)
5. DELETE /tasks/:id soft deletes task
6. Moving task to different column updates column_id and position
7. Authorization: Anyone in tenant can create; owner/assignee/admin can update/delete

## Dev Notes

### Architecture Context

**Service**: Kanban Service API  
[Source: architecture/component-architecture.md#kanban-service]

**Task Management**:  
Tasks belong to columns and boards. Position determines order within column.

**Position Auto-Assignment**:  
New tasks are placed at bottom of column (max position + 1).

**Task Movement**:  
Moving task to different column updates column_id and position. Board_id remains unchanged (denormalized).

### Previous Story Insights

**Story 4.1**: Database schema with tasks table  
**Story 4.2**: Board management and authorization patterns  
**Story 4.3**: Column management with position ordering

### Authorization Logic

**Create**: Anyone in tenant  
**Update/Delete**: Task assignee, board owner, or tenant admin

### API Endpoints

**POST /api/v1/columns/:columnId/tasks**  
Create task

Request:
```json
{
  "title": "Complete feature X",
  "description": "Implement user authentication",
  "assigned_to": "user-uuid",
  "priority": "high",
  "due_date": "2025-01-20T00:00:00Z"
}
```

**GET /api/v1/tasks/:id**  
Get task with comments

**PATCH /api/v1/tasks/:id**  
Update task

**PATCH /api/v1/tasks/:id/move**  
Move task to different column

Request:
```json
{
  "columnId": "new-column-uuid",
  "position": 0
}
```

**DELETE /api/v1/tasks/:id**  
Soft delete task
