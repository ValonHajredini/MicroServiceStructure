# Story 4.2: Kanban API - Board Management

## Status
Draft

## Story

**As a** user,
**I want** to create and manage Kanban boards,
**so that** I can organize different projects or workflows.

## Acceptance Criteria

1. POST /boards endpoint creates board with name, description, owner_id (from JWT)
2. Board automatically scoped to tenant_id from JWT
3. GET /boards endpoint returns tenant's boards with pagination
4. GET /boards/:id endpoint returns board with columns and tasks
5. PATCH /boards/:id endpoint updates name and description
6. DELETE /boards/:id soft deletes board and cascades to columns/tasks
7. Authorization: Owner or tenant admin can modify/delete boards

## Dev Notes

### Architecture Context

**Service**: Kanban Service API  
[Source: architecture/component-architecture.md#kanban-service]

**API Design**: RESTful with URL versioning (/api/v1/)  
[Source: architecture/api-contracts-communication.md#api-design-principles]

**Standard Response Format**:  
[Source: architecture/api-contracts-communication.md#standard-response-format]

Success Response:
```json
{
  "success": true,
  "data": {...},
  "meta": {
    "timestamp": "2025-01-14T10:00:00Z"
  }
}
```

Paginated Response:
```json
{
  "success": true,
  "data": [...],
  "meta": {
    "page": 1,
    "limit": 20,
    "total": 100,
    "totalPages": 5
  }
}
```

Error Response:
```json
{
  "success": false,
  "error": {
    "code": "NOT_FOUND",
    "message": "Board not found"
  },
  "meta": {
    "timestamp": "2025-01-14T10:00:00Z"
  }
}
```

### Authentication & Authorization

**JWT Authentication**:  
[Source: architecture/authentication-multi-tenancy.md#jwt-based-sso-flow]

- JWT validated via JwtStrategy
- User context attached to request (userId, tenantId, roles)
- All endpoints require JWT authentication

**Authorization Logic**:  
[Source: architecture/component-architecture.md#kanban-service]

- Board owner (board.owner_id === userId) can modify/delete
- Tenant admin (roles includes 'admin') can modify/delete
- Other users cannot modify/delete boards

**Tenant Scoping**:  
[Source: architecture/authentication-multi-tenancy.md#multi-tenancy-implementation]

- All queries automatically filtered by tenant_id from JWT
- Cannot access boards from other tenants

### API Endpoints

**POST /api/v1/boards**  
Create a new board

Request:
```json
{
  "name": "Project Alpha",
  "description": "Main project board"
}
```

Response:
```json
{
  "success": true,
  "data": {
    "id": "board-uuid",
    "tenant_id": "tenant-uuid",
    "owner_id": "user-uuid",
    "name": "Project Alpha",
    "description": "Main project board",
    "created_at": "2025-01-14T10:00:00Z",
    "updated_at": "2025-01-14T10:00:00Z"
  }
}
```

**GET /api/v1/boards?page=1&limit=20**  
List tenant's boards with pagination

Response:
```json
{
  "success": true,
  "data": [
    {
      "id": "board-uuid",
      "name": "Project Alpha",
      "description": "Main project board",
      "created_at": "2025-01-14T10:00:00Z"
    }
  ],
  "meta": {
    "page": 1,
    "limit": 20,
    "total": 5,
    "totalPages": 1
  }
}
```

**GET /api/v1/boards/:id**  
Get board with columns and tasks

Response:
```json
{
  "success": true,
  "data": {
    "id": "board-uuid",
    "name": "Project Alpha",
    "description": "Main project board",
    "columns": [
      {
        "id": "column-uuid",
        "title": "To Do",
        "position": 0,
        "tasks": [
          {
            "id": "task-uuid",
            "title": "Task 1",
            "position": 0
          }
        ]
      }
    ]
  }
}
```

**PATCH /api/v1/boards/:id**  
Update board

Request:
```json
{
  "name": "Updated Name",
  "description": "Updated description"
}
```

**DELETE /api/v1/boards/:id**  
Soft delete board (cascades to columns and tasks)
