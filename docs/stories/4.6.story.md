### Completion Notes List

**Decision: WebSocket with Polling Fallback**

Rationale:
- **Real-time requirement**: Story AC requires 5-second update delivery. WebSocket provides sub-second latency vs polling's 5s minimum.
- **Collaborative nature**: Kanban boards involve multiple users making simultaneous changes (tasks, columns, comments). WebSocket's bi-directional communication enables instant synchronization.
- **NestJS support**: First-class WebSocket integration via @nestjs/websockets reduces implementation complexity.
- **Fallback coverage**: Task 5 includes polling fallback, ensuring reliability when WebSocket fails (network issues, proxy restrictions).
- **Infrastructure**: Socket.io handles reconnection, heartbeat, and room management automatically.

Trade-offs accepted:
- Increased complexity vs polling (mitigated by NestJS abstractions)
- Persistent connections (managed by Socket.io connection pooling)
- Fallback to polling maintains minimum viable functionality
