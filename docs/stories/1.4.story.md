# Story 1.4: Core Authentication Service - User Registration & Login

## Status
Done

## Story

**As a** new user,
**I want** to register with email/password and login to receive JWT token,
**so that** I can access the platform securely.

## Acceptance Criteria

1. POST /auth/register endpoint accepts email, password, firstName, lastName
2. Passwords hashed using bcrypt with 10 salt rounds before storage
3. User record created in core_db.users table with tenant_id (auto-created for first user)
4. Email validation prevents duplicate registrations
5. POST /auth/login endpoint validates credentials and returns JWT token
6. JWT includes claims: userId, tenantId, roles: ['user'], enabledServices: []
7. Token expiration set to 24 hours
8. Basic error handling: invalid credentials, duplicate email, weak password

### Registration Flow Logic

[Source: architecture/authentication-multi-tenancy.md#jwt-based-sso-flow]

**Step-by-step registration process:**

1. **Validate Input:**
   - Email format valid
   - Password meets strength requirements (min 8 chars, complexity)
   - Required fields present (email, password, firstName, lastName)

2. **Check for Duplicate Email:**
   - Query: `SELECT * FROM users WHERE email = ?`
   - Note: Email is unique per tenant, but registration creates tenant first
   - If user exists with this email in ANY tenant: reject (409 Conflict)

3. **Create or Find Tenant:**
   - For first user: Create new tenant with name from email domain or "Organization"
   - Set tenant.enabled_services = [] (empty array)
   - Set tenant.status = 'active'

4. **Hash Password:**
   - Use bcrypt with 10 salt rounds
   - Store only password_hash, NEVER plain password

5. **Create User Record:**
   - Set tenant_id from created tenant
   - Set email, password_hash, first_name, last_name
   - Set status = 'active'

6. **Assign Role:**
   - Create user_tenant_role record
   - Role = 'admin' for first user in tenant, 'user' for subsequent users
   - Link user_id and tenant_id

7. **Return Success:**
   - HTTP 201 Created
   - Return: { message: 'Registration successful', userId, tenantId }
   - Do NOT return password_hash or sensitive data

### Login Flow Logic

[Source: architecture/authentication-multi-tenancy.md#jwt-based-sso-flow]

**Step-by-step login process:**

1. **Validate Input:**
   - Email and password provided

2. **Find User:**
   - Query: `SELECT * FROM users WHERE email = ?`
   - Include tenant and roles in query (JOIN)

3. **Verify Password:**
   - Use bcrypt.compare(plainPassword, user.password_hash)
   - If invalid: return 401 Unauthorized with generic message

4. **Check User Status:**
   - If user.status !== 'active': return 403 Forbidden

5. **Generate JWT Token:**
   - Create payload with claims:
     ```typescript
     {
       sub: user.id,
       email: user.email,
       tenantId: user.tenant_id,
       roles: ['admin'],  // from user_tenant_roles
       enabledServices: user.tenant.enabled_services,
       iat: timestamp,
       exp: timestamp + 24h
     }
     ```
   - Sign with JWT_SECRET using HS256

6. **Return Response:**
   - HTTP 200 OK
   - Return: { access_token: jwt, user: { id, email, firstName, lastName, tenantId } }
   - Do NOT return password_hash

### Security Requirements

[Source: architecture/security-architecture.md#security-checklist]

1. **Password Security:**
   - Bcrypt with 10 salt rounds
   - Never log or return password_hash
   - Enforce minimum password strength

2. **Email Validation:**
   - Format validation using class-validator
   - Prevent duplicate registrations
   - Case-insensitive email comparison

3. **JWT Security:**
   - Store JWT_SECRET in environment variable
   - Use HS256 algorithm (explicit)
   - Set 24-hour expiration
   - Include all required claims

4. **Error Handling:**
   - Generic error messages for login failures (don't reveal if email exists)
   - Log authentication failures for monitoring
   - Rate limiting (future enhancement - note in code comments)

### DTOs with Validation

**RegisterDto:**
```typescript
import { IsEmail, IsString, MinLength, Matches } from 'class-validator';

export class RegisterDto {
  @IsEmail()
  email: string;

  @IsString()
  @MinLength(8)
  @Matches(/((?=.*\d)|(?=.*\W+))(?![.\n])(?=.*[A-Z])(?=.*[a-z]).*$/, {
    message: 'Password must contain uppercase, lowercase, and number/special char'
  })
  password: string;

  @IsString()
  @MinLength(1)
  firstName: string;

  @IsString()
  @MinLength(1)
  lastName: string;
}
```

**LoginDto:**
```typescript
export class LoginDto {
  @IsEmail()
  email: string;

  @IsString()
  @MinLength(1)
  password: string;
}
```
