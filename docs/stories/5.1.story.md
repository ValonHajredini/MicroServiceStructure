# Story 5.1: Docker Containerization - All Services

## Status
Draft

## Story

**As a** DevOps engineer,
**I want** Docker containers for all services with optimized builds,
**so that** we have consistent deployment across environments.

## Acceptance Criteria

1. Dockerfile for each service: core-api, core-ui, notes-api, notes-ui, kanban-api, kanban-ui
2. Multi-stage builds: build stage + production stage minimizing image size
3. Docker Compose orchestration file running all services + databases locally
4. Environment variable configuration for all services (database URLs, JWT secrets, API URLs)
5. Health check commands configured in Docker Compose
6. docker-compose up successfully starts entire platform on clean machine
7. Documentation in docs/deployment/docker-setup.md

## Tasks / Subtasks

- [ ] Task 1: Audit Existing Container Assets (AC: 1, 2)
  - [ ] Inventory current Dockerfiles under `apps/*` and note gaps per service
  - [ ] Confirm Nx/Turborepo build outputs required for production launch of Angular and NestJS services
  - [ ] Document required base images and runtime versions for Dockerfiles referencing tech stack notes (Node 18+, Angular CLI)

- [ ] Task 2: Create Multi-Stage Dockerfiles (AC: 1, 2)
  - [ ] Author optimized Dockerfiles for `apps/core-api`, `apps/notes-api`, `apps/kanban-api`, `apps/admin-api` with build + runtime stages
  - [ ] Author optimized Dockerfiles for `apps/core-ui`, `apps/notes-ui`, `apps/kanban-ui` that build Angular artifacts then serve via Nginx
  - [ ] Ensure runtime stages copy only compiled artifacts, node_modules (production), and required configuration files
  - [ ] Parameterize environment variables with defaults for local usage (e.g., `ARG NODE_ENV=production`)

- [ ] Task 3: Define Docker Compose Orchestration (AC: 3, 4, 5)
  - [ ] Create/update root-level `docker-compose.yml` including all APIs, UIs, PostgreSQL databases, and shared services
  - [ ] Configure service dependencies, shared networks, and named volumes for persistent Postgres storage
  - [ ] Map environment variables for each container (DB URLs, JWT secret, service URLs) aligning with `.env` files
  - [ ] Add `healthcheck` definitions per container targeting `/health` or equivalent endpoints

- [ ] Task 4: Local Developer Configuration (AC: 4, 6)
  - [ ] Provide `.env.docker` template with all required variables and safe defaults
  - [ ] Verify local secrets (JWT, DigitalOcean Spaces keys) load via Compose `.env` file
  - [ ] Execute `docker compose build` followed by `docker compose up` on a machine without prior images to confirm bootstrap
  - [ ] Capture any manual steps (seed data, migrations) needed post-startup

- [ ] Task 5: Documentation Deliverables (AC: 7)
  - [ ] Create or update `docs/deployment/docker-setup.md` with build instructions, prerequisites, and troubleshooting
  - [ ] Document health check expectations and container restart policies
  - [ ] Include guidance for syncing environment variables with GitHub Actions secrets and DigitalOcean deployment

- [ ] Task 6: Validation & Handoff (AC: 5, 6, 7)
  - [ ] Run smoke tests verifying API `/health` endpoints and Angular frontends load while running via Compose
  - [ ] Capture evidence (logs, screenshots, commands) for inclusion in story completion notes
  - [ ] Share Compose usage instructions with team (README update or Slack announcement)

## Dev Notes

### Previous Story Insights
- Story 4.10 (Kanban UI real-time updates) remains in Draft with no Dev Agent learnings to leverage yet.

### Data Models
- Containerization does not alter schemas but depends on service-specific Postgres databases: `core_db`, `notes_db`, `kanban_db`, and `admin_db` provisioned per service. Compose configuration must point to these logical databases.  
  [Source: architecture/database-architecture.md#database-per-service-strategy]

### API Specifications
- Existing REST endpoints for Core, Notes, Kanban, and Admin services remain unchanged; containers must expose the same port mappings defined in the architecture overview.  
  [Source: architecture/component-architecture.md#core-service]  
  [Source: architecture/component-architecture.md#notes-service]  
  [Source: architecture/component-architecture.md#kanban-service]  
  [Source: architecture/component-architecture.md#admin-service]

### Component Specifications
- Each service resides under `apps/{service-name}` with NestJS or Angular structure as documented. Docker build contexts should align with these directories and include Nx/Turborepo workspace configuration.  
  [Source: architecture/component-architecture.md#core-service]

### File Locations
- Root-level Compose file and per-service Dockerfiles follow the deployment blueprint that places build contexts alongside service directories.  
  [Source: architecture/infrastructure-deployment.md#deployment-architecture]
- Document deliverables belong under `docs/deployment/` per infrastructure guidelines.  
  [Source: architecture/infrastructure-deployment.md#deployment-architecture]

### Testing Requirements
- No dedicated testing-strategy document is available in architecture materials; verify runtime readiness by exercising service health endpoints once containers are running.

### Technical Constraints
- Compose sample mandates explicit environment variable wiring, Postgres images, and dependency ordering for startup. Mirror service names, ports, and volume usage to maintain interoperability with DigitalOcean deployments.  
  [Source: architecture/infrastructure-deployment.md#deployment-architecture]
- Maintain JWT secret distribution and DigitalOcean Spaces credentials via environment variables as outlined in the authentication and storage configuration.  
  [Source: architecture/authentication-multi-tenancy.md#security-considerations]

### Testing Standards

- Validate `docker compose build` and `docker compose up` succeed without manual intervention beyond environment file provisioning.  
- Hit `/health` (or analogous) endpoints for API services to confirm health checks align with Compose configuration.  
- Perform a basic UI smoke test to ensure Angular frontends serve via containerized Nginx after the build.
