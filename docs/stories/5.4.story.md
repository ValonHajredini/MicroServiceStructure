# Story 5.4: Security Hardening

## Status
Draft

## Story

**As a** security-conscious user,
**I want** platform secured against common vulnerabilities,
**so that** my data is protected.

## Acceptance Criteria

1. HTTPS enforced on all domains with TLS 1.2+ certificates (Let's Encrypt or DigitalOcean)
2. CORS configured whitelist specific to service subdomains (no wildcard *)
3. Content Security Policy headers configured preventing XSS attacks
4. Rate limiting implemented on authentication endpoints (10 requests/minute per IP)
5. SQL injection protection verified through TypeORM parameterized queries
6. Helmet.js middleware configured for security headers on all NestJS services
7. Security audit checklist completed and documented in docs/security-audit.md

## Tasks / Subtasks

- [ ] Task 1: TLS Enforcement (AC: 1)
  - [ ] Configure HTTPS certificates (Let's Encrypt / DigitalOcean) for `mydomain.com`, `notes.mydomain.com`, `kanban.mydomain.com`, `api.mydomain.com`
  - [ ] Update Nginx/App Platform settings to redirect HTTP → HTTPS and enforce TLS 1.2+
  - [ ] Document renewal automation (certbot or DigitalOcean-managed certificates)

- [ ] Task 2: Harden Service Middleware (AC: 2, 3, 4, 6)
  - [ ] Update NestJS bootstrap (`main.ts`) for all services to enable strict CORS whitelist matching architecture domains
  - [ ] Integrate Helmet middleware with CSP configuration blocking inline scripts, restricting allowed origins
  - [ ] Implement rate limiting (e.g., `@nestjs/throttler`) on authentication endpoints with 10 requests/min/IP

- [ ] Task 3: Verify Data Layer Protections (AC: 5)
  - [ ] Audit repositories and services for raw SQL usage; ensure TypeORM parameter binding used everywhere
  - [ ] Add automated tests demonstrating rejected SQL injection attempts on critical endpoints
  - [ ] Update developer guidelines to avoid string interpolation in queries

- [ ] Task 4: Infrastructure Configuration Review (AC: 1, 2, 3)
  - [ ] Confirm DigitalOcean firewall settings limit inbound traffic to required ports (80/443/22)
  - [ ] Ensure Docker Compose/Nginx configurations propagate security headers and do not expose internal ports publicly
  - [ ] Validate load balancer or reverse proxy passes `X-Forwarded-Proto` for HTTPS awareness

- [ ] Task 5: Documentation & Audit (AC: 7)
  - [ ] Complete security checklist documenting implemented controls in `docs/security-audit.md`
  - [ ] Capture evidence (screenshots, command output) for TLS, CORS, CSP, rate limiting, and SQL injection tests
  - [ ] Update onboarding docs with security configuration expectations for future services

- [ ] Task 6: Regression & Monitoring (AC: 6, 7)
  - [ ] Add automated regression tests verifying security middleware present during application bootstrap
  - [ ] Integrate security checks into CI pipeline (e.g., ensure lint/test stage asserts required modules configured)
  - [ ] Schedule recurring review of security controls and include entry in operations runbook
