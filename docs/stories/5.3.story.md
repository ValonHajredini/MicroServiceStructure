# Story 5.3: API Documentation - Swagger/OpenAPI

## Status
Draft (Partially implemented)

## Current State

✅ **Existing:**
- core-api has Swagger at /api/docs
- notes-api has Swagger at /api/docs

❌ **Missing:**
- kanban-api has NO Swagger configuration
- No unified documentation gateway
- DTOs lack @ApiProperty decorators
- No OpenAPI spec export

## Prerequisites

- [ ] **Configure Swagger on kanban-api** (CRITICAL - Missing entirely)
  - Install @nestjs/swagger
  - Configure SwaggerModule in main.ts
  - Add /api/docs endpoint
- [ ] **Add @ApiProperty decorators to libs/shared-types DTOs**
  - Document all request/response DTOs
  - Add examples and validation metadata
- [ ] **Document unified docs gateway approach**
  - Option 1: Nginx reverse proxy aggregating all /api/docs
  - Option 2: Separate docs service combining OpenAPI specs

## Story

**As a** developer using the platform API,
**I want** comprehensive Swagger documentation for all endpoints,
**so that** I can integrate with services programmatically.

## Acceptance Criteria

1. @nestjs/swagger fully configured on all API services (Core, Notes, Kanban)
2. All endpoints documented with: ApiTags, ApiOperation, ApiResponse decorators
3. Request/response DTOs documented with ApiProperty decorators
4. Authentication documented: JWT Bearer token requirement noted
5. Swagger UI accessible at: api.mydomain.com/docs (unified), notes-api/docs, kanban-api/docs
6. Example requests/responses included for complex endpoints
7. OpenAPI 3.0 spec downloadable for external tools (Postman, SDK generation)

## Tasks / Subtasks

- [ ] Task 1: Enable Swagger in Each NestJS Service (AC: 1, 5, 7)
  - [ ] Add `@nestjs/swagger` dependencies and configure SwaggerModule in `main.ts` for core-api, notes-api, kanban-api
  - [ ] Define document metadata (title, description, version) aligning with service naming conventions
  - [ ] Expose JSON spec endpoints at `/docs-json` for download (e.g., `/api/v1/docs-json`)

- [ ] Task 2: Document Controllers and Endpoints (AC: 2, 4, 6)
  - [ ] Annotate controllers with `@ApiTags` using domain-specific vocabulary (Auth, Tenants, Notes, Boards)
  - [ ] Add `@ApiOperation`, `@ApiResponse`, and `@ApiBearerAuth` where JWT auth required
  - [ ] Provide example responses using `@ApiResponse({ schema: ... })` or DTO examples for complex payloads

- [ ] Task 3: Enrich DTOs with ApiProperty Metadata (AC: 3, 6)
  - [ ] Add `@ApiProperty` (and `@ApiPropertyOptional`) to request/response DTO classes across services
  - [ ] Document enums, formats, and example values for IDs, timestamps, and nested objects
  - [ ] Ensure shared DTOs in `libs/shared-types` also include Swagger metadata

- [ ] Task 4: Implement Unified Documentation Gateway (AC: 5, 7)
  - [ ] Create aggregation endpoint (e.g., in core-api or gateway) serving consolidated Swagger UI at `api.mydomain.com/docs`
  - [ ] Configure reverse proxy or route mapping so unified docs proxy service-specific specs
  - [ ] Provide download links for each service's OpenAPI spec from unified interface

- [ ] Task 5: Authentication & Security Documentation (AC: 4, 6)
  - [ ] Highlight JWT Bearer requirements within Swagger config and descriptions
  - [ ] Document tenant isolation expectations and required headers in examples
  - [ ] Include error response schemas referencing standard error format

- [ ] Task 6: Validation & Documentation (AC: 6, 7)
  - [ ] Smoke test docs endpoints locally (via Docker Compose) and in staging environment
  - [ ] Update `docs/api/swagger.md` (create if missing) with instructions for accessing docs and regenerating specs
  - [ ] Capture screenshots or recordings showing documentation completeness for sign-off

  [Source: architecture/api-contracts-communication.md#api-design-principles]

### Component Specifications
- Swagger configuration should live in each service’s `main.ts` and integrate with NestJS modules per service architecture.  
  [Source: architecture/component-architecture.md#core-service]

### File Locations
- Place Swagger setup in each service entry point (`apps/{service}/src/main.ts`) and expose static assets under `/docs`. Documentation artifacts reside in `docs/api/`.  
  [Source: architecture/api-contracts-communication.md#api-design-principles]

### Testing Requirements
- No formal testing guidelines captured in architecture docs. Verify docs endpoints through automated smoke tests (e.g., Jest + Supertest) ensuring `/docs-json` returns valid OpenAPI schema.

### Technical Constraints
- JWT authentication, tenant isolation, and shared response format must be reflected in documentation to align with security considerations.  
  [Source: architecture/authentication-multi-tenancy.md#security-considerations]  
  [Source: architecture/security-architecture.md#security-checklist]

### Testing Standards

- Validate OpenAPI JSON against a schema validator to catch structural issues.  
- Run automated requests against `/docs` endpoints within CI to detect regressions after deployments.  
- Manually confirm example requests execute successfully via Swagger UI for high-value endpoints (auth, notes, kanban).
