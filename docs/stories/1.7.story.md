### Health Check Endpoints

[Source: architecture/component-architecture.md#core-service]

**GET /health - Liveness Check**

Simple check that service is running. No external dependencies.

**Request:**
```
GET /api/v1/health
```

**Response:**
```json
{
  "status": "ok",
  "service": "core-api",
  "version": "1.0.0",
  "timestamp": "2025-10-29T10:00:00Z"
}
```

**GET /ready - Readiness Check**

Checks if service is ready to handle requests (database connected).

**Request:**
```
GET /api/v1/ready
```

**Response (Success - Database Connected):**
```json
{
  "status": "ready",
  "database": "connected",
  "timestamp": "2025-10-29T10:00:00Z"
}
```

**Response (Failure - Database Down):**
```
HTTP 503 Service Unavailable

{
  "status": "not ready",
  "database": "disconnected",
  "timestamp": "2025-10-29T10:00:00Z"
}
```

### HealthController Implementation

```typescript
@Controller('health')
export class HealthController {
  constructor(private dataSource: DataSource) {}

  @Get()
  health() {
    return {
      status: 'ok',
      service: 'core-api',
      version: process.env.npm_package_version || '1.0.0',
      timestamp: new Date().toISOString()
    };
  }

  @Get('ready')
  async ready() {
    try {
      // Simple database connectivity check
      await this.dataSource.query('SELECT 1');
      return {
        status: 'ready',
        database: 'connected',
        timestamp: new Date().toISOString()
      };
    } catch (error) {
      throw new ServiceUnavailableException({
        status: 'not ready',
        database: 'disconnected',
        timestamp: new Date().toISOString()
      });
    }
  }
}
```

### Dockerfile - Multi-Stage Build

[Source: architecture/infrastructure-deployment.md#deployment-architecture]

```dockerfile
# Build stage
FROM node:18-alpine AS builder

WORKDIR /app

# Copy package files
COPY package*.json ./
COPY turbo.json ./

# Install dependencies
RUN npm ci

# Copy source code
COPY . .

# Build application
RUN npm run build

# Production stage
FROM node:18-alpine

WORKDIR /app

# Copy package files
COPY package*.json ./

# Install production dependencies only
RUN npm ci --omit=dev

# Copy built application from builder
COPY --from=builder /app/dist ./dist

# Create non-root user
RUN addgroup -g 1001 -S nodejs && \
    adduser -S nestjs -u 1001

# Change ownership
RUN chown -R nestjs:nodejs /app

# Switch to non-root user
USER nestjs

# Expose port
EXPOSE 3000

# Health check
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
  CMD node -e "require('http').get('http://localhost:3000/health', (r) => {process.exit(r.statusCode === 200 ? 0 : 1)})"

# Start application
CMD ["node", "dist/main"]
```

**Optimization Benefits:**
- Multi-stage build reduces final image size (dev dependencies excluded)
- Alpine Linux base image is minimal (5MB vs 900MB for full Node image)
- Non-root user improves security
- Health check enables container orchestration

### Docker Compose Configuration

[Source: architecture/infrastructure-deployment.md#deployment-architecture]

```yaml
version: '3.8'

services:
  postgres:
    image: postgres:14-alpine
    container_name: core-db
    environment:
      POSTGRES_DB: core_db
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - microservices

  core-api:
    build:
      context: ./apps/core-api
      dockerfile: Dockerfile
    container_name: core-api
    environment:
      - NODE_ENV=development
      - PORT=3000
      - DATABASE_URL=postgresql://postgres:postgres@postgres:5432/core_db
      - JWT_SECRET=${JWT_SECRET:-your-super-secret-jwt-key-change-in-production}
      - JWT_EXPIRATION=24h
      - BCRYPT_ROUNDS=10
      - SENDGRID_API_KEY=${SENDGRID_API_KEY}
      - EMAIL_FROM=${EMAIL_FROM:-noreply@yourdomain.com}
      - FRONTEND_URL=${FRONTEND_URL:-http://localhost:4200}
    ports:
      - "3001:3000"
    depends_on:
      postgres:
        condition: service_healthy
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:3000/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 40s
    networks:
      - microservices

volumes:
  postgres_data:

networks:
  microservices:
    driver: bridge
```

**Key Features:**
- PostgreSQL with persistent volume
- Health checks for both services
- core-api waits for PostgreSQL to be healthy
- Environment variables with defaults
- Network isolation

### Local Setup Documentation

**docs/deployment/local-setup.md Structure:**

1. **Prerequisites**
   - Docker and Docker Compose installed
   - Node.js 18+ (for local development)
   - Git

2. **Environment Setup**
   - Copy .env.example to .env
   - Update environment variables (especially JWT_SECRET)
   - Configure email service credentials

3. **Running with Docker Compose**
   - `docker-compose up -d` - Start services
   - `docker-compose logs -f core-api` - View logs
   - `docker-compose down` - Stop services

4. **Health Checks**
   - `curl http://localhost:3001/health` - Liveness check
   - `curl http://localhost:3001/ready` - Readiness check

5. **Database Migrations**
   - `docker-compose exec core-api npm run migration:run`
   - `docker-compose exec core-api npm run migration:revert`

6. **Testing Endpoints**
   - Registration: `POST http://localhost:3001/auth/register`
   - Login: `POST http://localhost:3001/auth/login`
   - API Docs: `http://localhost:3001/api/docs`

7. **Troubleshooting**
   - Database connection errors
   - Port conflicts
   - Environment variable issues
   - Container restart loops

### Testing

#### Test Requirements

**Integration Tests:**
1. GET /health returns 200 OK
2. GET /ready returns 200 when database connected
3. GET /ready returns 503 when database disconnected
4. Docker Compose starts all services successfully
5. Health checks work inside Docker containers
6. Database migrations run successfully in container
7. All authentication endpoints work via Docker Compose

**Deployment Tests:**
1. Build Dockerfile successfully
2. Docker image size is optimized (< 200MB)
3. Container runs as non-root user
4. Health check passes after container start
5. Container restarts on health check failure
6. Environment variables loaded correctly
7. PostgreSQL data persists across container restarts

#### Verification Steps

1. **Build and Start:**
   - `docker-compose build`
   - `docker-compose up -d`
   - Wait for health checks to pass

2. **Test Health Endpoints:**
   - `curl http://localhost:3001/health` (should return 200)
   - `curl http://localhost:3001/ready` (should return 200)

3. **Test Database Connectivity:**
   - Stop PostgreSQL: `docker-compose stop postgres`
   - `curl http://localhost:3001/ready` (should return 503)
   - Start PostgreSQL: `docker-compose start postgres`
   - Wait for health check, test /ready again (should return 200)

4. **Test Application Functionality:**
   - Register user: `POST http://localhost:3001/auth/register`
   - Login: `POST http://localhost:3001/auth/login`
   - Verify database persistence across restarts

5. **Verify Security:**
   - `docker-compose exec core-api whoami` (should be 'nestjs', not 'root')
   - Check image size: `docker images | grep core-api`

6. **Test Data Persistence:**
   - Create user via registration
   - `docker-compose down`
   - `docker-compose up -d`
   - Login with created user (should work)

### Important Notes

1. **Health vs Ready:** /health checks if service is alive (fast). /ready checks if service can handle requests (validates dependencies).

2. **Docker Optimization:** Multi-stage build significantly reduces image size. Production stage contains only runtime dependencies.

3. **Security:** Container runs as non-root user (nestjs:1001) to minimize attack surface.

4. **Data Persistence:** PostgreSQL data stored in Docker volume (persists across container restarts).

5. **Development Workflow:** Use Docker Compose for local development to match production environment.

6. **Environment Variables:** Never commit .env file. Always use .env.example as template.

7. **Port Mapping:** PostgreSQL on 5432, core-api on 3001 (mapped from container's 3000) to avoid conflicts.
